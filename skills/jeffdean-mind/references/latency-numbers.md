# Numbers Everyone Should Know

Jeff Dean이 2009년 LADIS 키노트 "Designs, Lessons and Advice from Building Large
Distributed Systems"에서 제시한 표. 뉴요커의 표현대로 이 수치들은 "Dean과 Ghemawat의
뇌에 하드와이어되어" 있으며, 모든 백오브엔벨로프 계산의 원재료다.

## 원본 수치 (2009)

| 연산 | 시간 |
|---|---|
| L1 캐시 참조 | 0.5 ns |
| 분기 예측 실패 (branch mispredict) | 5 ns |
| L2 캐시 참조 | 7 ns |
| 뮤텍스 lock/unlock | 25 ns |
| 메인 메모리 참조 | 100 ns |
| Zippy로 1KB 압축 | 3,000 ns (3 µs) |
| 1Gbps 네트워크로 2KB 전송 | 20,000 ns (20 µs) |
| 메모리에서 1MB 순차 읽기 | 250,000 ns (250 µs) |
| 같은 데이터센터 내 왕복 (round trip) | 500,000 ns (500 µs) |
| 디스크 seek | 10,000,000 ns (10 ms) |
| 디스크에서 1MB 순차 읽기 | 20,000,000 ns (20 ms) |
| 패킷 CA→네덜란드→CA 왕복 | 150,000,000 ns (150 ms) |

## 표에서 읽어야 할 자릿수 직관

- 메모리는 디스크보다 순차 읽기에서 ~100배 빠르다. 디스크 seek은 메모리 참조보다
  ~100,000배 느리다.
- 같은 데이터센터 왕복(0.5ms)은 메모리 1MB 읽기(0.25ms)의 2배 — 네트워크 한 홉은
  "공짜"가 아니다.
- 압축은 싸다: 1KB 압축(3µs)은 1Gbps로 2KB를 보내는 것(20µs)보다 싸다. 대역폭이
  귀할 때는 CPU를 태워 압축하라.
- 대륙 간 왕복(150ms)은 데이터센터 내 왕복의 300배. 지리적 분산은 설계를 지배한다.

## 현대화 보정 (주의사항)

이 수치는 10년 이상 지난 값이다. **절대값이 아니라 자릿수(order of magnitude)
직관으로 사용해야 한다.** 특히:

- 디스크 항목: SSD/NVMe 등장으로 크게 개선 (NVMe 랜덤 읽기 ~10–100µs 수준,
  회전 디스크 seek 10ms와 자릿수가 다르다).
- 네트워크: 10/25/100GbE 보급으로 전송 항목 개선. 단, 데이터센터 내 왕복의
  자릿수(수백 µs)와 대륙 간 왕복(수십~수백 ms, 광속의 한계)은 여전히 유효.
- L1/L2/메모리/분기 예측/뮤텍스 수치는 오늘날에도 거의 그대로 유효하다.

계산에 쓸 때는 사용하는 수치의 연대를 명시하고, 대상 환경(클라우드, NVMe, RDMA 등)에
맞게 보정하라.

## 참고: Zippy vs gzip 트레이드오프 (인코딩 철학의 예)

| | 인코딩 | 디코딩 | 압축률 |
|---|---|---|---|
| Zippy (Snappy) | ~300 MB/s | ~600 MB/s | 2–4배 |
| gzip | ~25 MB/s | ~200 MB/s | 4–6배 |

"CPU는 빠르고 메모리/대역폭은 귀하다" — 어느 쪽을 태울지는 항상 수치로 저울질한다.
